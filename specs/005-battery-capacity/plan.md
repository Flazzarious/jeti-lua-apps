# Implementation Plan: Battery Capacity

**Branch**: `feature/005-battery-capacity` (merges to `develop`, then `main` on release) | **Date**: 2026-11-01 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/005-battery-capacity/spec.md`

## Summary

A new app, **Battery Capacity** (`src/Apps/AG-BatCp.lua`), that shows up to
four battery packs per model as solid battery gauges, one on its side in the
small telemetry window and up to four upright in the double window. It
speaks capacity callouts, a low-voltage alarm, an optional current alarm,
session max current and an optional "pack not full" check in the Amy voice.
Category and chemistry defaults keep setup short.

Approach:

- **One app file plus one small new lib module**, `ag_peak.lua`, holding
  Speed Gauge's spike-filtered max as a stateless function (R7). Speed Gauge
  itself is not touched in this feature.
- **Two cadences**: a 200 ms tick reads sensors and runs the timing-
  sensitive parts (alarm delays, max filter); a 1 s tick computes %, bands,
  callout levels, new-pack detection and rebuilds display strings (R2).
- **Sensor unit decides the capacity mode** (mAh, Ah, %, V), resolved once
  in the settings form and saved, so `loop()` only uses the light sensor
  call (R1). Voltage-only packs use a fixed resting curve per chemistry,
  smoothed and held under load (R3).
- **New pack vs brown-out** from a three-state telemetry tracker and a
  20-point rise check, cross-checked by voltage when available (R4).
- **18 `pSave` keys**: six app keys (incl. the window titles) plus a pack array, an alarm array and a
  string array per battery (R5).
- **Pending-flag callout scheduler**, no queue: FR-034a's priority order,
  one phrase per dispatch, nothing queues twice, transmitter fallback with
  the pilot's voice-name file (R9).
- **Gauges drawn at runtime** with plain opaque rectangles in the theme's
  colours and fixed band colours, straddling % text drawn twice with
  clipping (R10).
- **Voice**: numbers copied from Speed Gauge's set, 17 words generated by a
  new `make_batcap.py` at the same pace (R8).
- **Testing without packs**: new emulator sensors and a `SIM` mode with
  scripted discharge, noise, spikes, swap and brown-out (R13).

## Technical Context

**Language/Version**: Lua 5.3.1 on the transmitter (32-bit integers and floats). Voice generator: Python 3.9+

**Primary Dependencies**: JETI DC/DS Lua API v1.5 as declared in `types/jeti.lua` (full list in research R14; no new stubs). New lib module `ag_peak` ([contract](contracts/lib-modules.md)). Generator only (not deployed): `piper-tts` with `en_US-amy-medium` (`C:\Users\aaron\piper-voices\`), `tools/voice/make_voice.py`'s helpers, Speed Gauge's committed number files

**Storage**: `system.pSave`/`pLoad`, per model, 18 keys ([data-model.md](data-model.md)). No files written by the app. 518 voice files plus `CREDITS.txt` and `index.txt` in `src/Apps/AG-BatCp/voice/` (about 20 MB, CC BY-SA 4.0), committed

**Testing**: `python tools/check.py`; LuaLS diagnostics; generator self-check; emulator scenarios with Emulated Telemetry and `SIM` profiles; transmitter checks for sound, layout, themes and sensor units; bench check of the voltage curves ([quickstart.md](quickstart.md))

**Target Platform**: JETI DS-24 II / DC-24 II, firmware 6.03+ (emulator 6.04). Transmitter windows 150 × 23 (small) and 150 × 68 (double); emulator 157 × 60 / 157 × 127 with the title inside. Callouts work on any DC/DS transmitter; the gauges need a DS-24 II

**Project Type**: Embedded transmitter app (Lua script, asset folder, one lib module) and a developer-side voice generator

**Performance Goals**: capacity callout within 1 s of the crossing (SC-007); alarms within delay + 1 s (SC-008, SC-009); max spoken within 1 s + 1 tick of the peak (SC-010); print functions under 10% CPU per call with four batteries; no CPU-limit errors over 30 minutes (SC-014)

**Constraints**: no allocation in `loop()` or print functions except rebuilding cached strings on the 1 s tick when values change; `system.getSensor*` called through `system` each time; `lcd` only in print functions; `form` only while the form is open; ≤ 30 persisted keys (18 used); ≤ 200 file-level locals (constants, tables and per-battery state grouped in tables); intbox values ≤ 32 767; no `os`/`debug`/`coroutine`/`bit32`; never `registerControl`/`setControl`/`setProperty`

**Scale/Scope**: app about 1,400–1,800 lines (Speed Gauge is 1,643, Flameout about 1,000); `ag_peak` about 40 lines; generator about 150 lines; 518 WAVs

Findings that differed from the spec's wording, accepted by Aaron and
written into the spec (FR-003, FR-006, edge cases, Clarifications) on
2026-11-01:

- **FR-006 "Full" for LiFe and NiMH is a charge voltage**, not a resting
  one; the gauge's 100% point is the resting curve's top (R3). Without this
  every fresh LiFe pack would read about 70% and fail the new-pack check.
- **FR-003 "refuse characters as typed"** isn't possible with
  `form.addTextbox`; the name is trimmed to fit on confirm (R6).
- **Default labels "BRAKES-2", "LIGHTS-2", "FLIGHT-2"** probably don't fit
  a 37-px slot; short forms "BRK", "LGT", "FLT" are ready if the width
  measurement (T2) says so (R6).

## Constitution Check

| Principle | Status | How the design complies |
| --- | --- | --- |

| IV. State resets on model switch | PASS | All session state built in `init()`; 18 `pSave` keys (ints, int arrays, string arrays); voltages in centivolts, delays in tenths; load clamps and compacts |
| V. Stable names, UTF-8 | PASS | `AG-BatCp.lua` (8.3, permanent from 0.1.0), assets in `AG-BatCp/`, absolute `/Apps/AG-BatCp/...` paths; module `ag_peak` in `lib/`; labels use ASCII |
| VI. Keep loop() light | PASS | 200 ms / 1 s ticks; `getSensorValueByID` only; units resolved in the form; strings rebuilt only on change at 1 s; phrase paths built only at dispatch; `getSensors` only when a subform opens |
| VII. Shared code in lib, stateless | PASS | New `ag_peak` (pure functions over a caller-owned table, no `lcd`/`form`/`system`). No existing module changed; Speed Gauge not migrated in this feature, so no other app needs re-verification (follow-up listed below) |
| VIII. License and credit | PASS | Original app: SPDX header in the app, module and generator. Layout sketches are original (spec). Piper (MIT) and Amy (CC BY-SA 4.0) credited in `voice/CREDITS.txt`, `CREDITS.md`, the README and the settings footer (FR-035). Number files copied from Speed Gauge's set carry the same credit |

## Implementation order

For `/speckit-tasks`. Each step leaves `check.py` passing.

1. **Measure first** (R6): probe `FONT_MINI` widths on the transmitter; fill
   `MINI_W`; decide short labels.
2. **Voice generator** (R8): `make_batcap.py`, generate, self-check; Aaron
   listens on the PC.
3. **`ag_peak`** ([contract](contracts/lib-modules.md)).
4. **App skeleton**: header, constants and tables, settings load/clamp/
   compact/save, derived values, `init` registering form and both windows,
   empty-state windows.
5. **Settings form** ([contract](contracts/settings-form.md)): main page,
   battery subform, sensor filtering, defaults and overwrite question,
   validation notes, live value, delete and reset.
6. **Capacity engine** ([data-model.md](data-model.md)): ticks, sensor
   reads, modes, voltage curve and smoothing, bands, telemetry tracker and
   new-pack detection.
7. **Windows** ([contract](contracts/telemetry-window.md)): double and small
   layouts, states, flash, straddle rule, cached strings.
8. **Callouts and alarms** ([contract](contracts/audio-events.md)): levels
   and repeats, low voltage, current alarm, max, new-pack check, scheduler,
   phrase building, fallback, voice check.
9. **Test support** (R13): emulator sensors, `SIM` profiles, `DEBUG_CPU`.
10. **Docs and credits**: README, CREDITS.md, CLAUDE.md, generator README,
    API notes.
11. **Validation**: quickstart sections 1–2 in the emulator; sections 3–4 on
    the transmitter and the bench (manual, reported by Aaron).

**Follow-ups outside this feature:** migrate Speed Gauge's max filter onto
`ag_peak` (needs Speed Gauge re-verification).
