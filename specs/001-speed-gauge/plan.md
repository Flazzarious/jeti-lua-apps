# Implementation Plan: Speed Gauge

**Branch**: `feature/001-speed-gauge` (Gitflow: merges to `develop`, then `main` on release) | **Date**: 2026-09-27, updated 2026-10-03 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/001-speed-gauge/spec.md`

## Summary

A new app, **Speed Gauge** (`src/Apps/AG-SpdGa.lua`), that re-implements DFM
Speed Announcer v2.1's callouts and warnings with clearer settings, adds an
optional air-density correction, and draws a speedometer modeled on the
spec's visual design reference (dark face, numbered scale, colored value arc,
overspeed zone, big center number, sticky session-max marker). It targets the
DS-24 II's measured Lua window sizes and shows a notice on other
transmitters.

**Update 2026-10-03.** Version 0.1.0 is built (every non-manual task in
tasks.md is done). The spec has since gained three changes, which this plan
update covers and which ship as 0.2.0:

- **One app voice** (US6, FR-030–FR-037): a Piper "Amy" voice set,
  generated by a script in `tools/voice/` (committed since 2026-10-03, FR-035), speaks every
  callout, warning and startup announcement. v2.1's audio is the fallback
  (research R13, R14).
- **Temperature source** (FR-038–FR-044): Standard / Manual / Sensor, with a
  live sensor such as the MSpeed's, a reject-and-resume rule, 1 °C
  hysteresis, a status line in settings and a Temperature row on the
  full-screen panel (R15, R17).
- **Narrower input limits** (FR-020): elevation −300 to 10,000 ft,
  temperature −20 to 130 °F, with clamping on load and a migration of the
  0.1.0 `tStd` setting (R16).

Approach:

- **One app file plus two shared modules.** `ag_dens` holds the ISA
  density math; `ag_gauge` holds dial geometry and arc drawing. Both are
  stateless (constitution VII). The 0.2.0 changes need **no module
  change**; voice and temperature logic stay in the app (R2's rule: no
  second user yet).
- **Two speeds per tick.** *Sensor speed* (calibrated, in the user's units)
  drives stall, landing and "airspeed alive". *Shown speed* (sensor speed ×
  density factor) drives the gauge, callouts, max and overspeed. This is the
  spec's Q1 clarification (FR-011). Sensor temperature changes only the
  density factor (FR-043).
- **Cheap per-tick work.** All conversion factors are folded into two
  multipliers when a setting changes. `loop()` does its work every 100 ms
  with two multiplies, a few comparisons and no string or table work. The
  temperature sensor is read every 5 s; voice paths are built only when a
  callout is due.
- **Two windows, three layouts.** A pilot-sized window (single 157 × 60 →
  compact arc; double 157 × 127 → round dial) and a full-screen window
  (320 × 260 → big dial plus side panel). One print function picks the layout
  from its `(w, h)` and draws from a layout cache (research R6, R7).
- **v2.1 kept where the spec is silent.** Callout timing and vibration
  profiles are unchanged; v2.1's sounds remain as the fallback. Every
  deliberate difference is listed in
  [research.md R11](research.md#r11-behavior-differences-from-dfm-speed-announcer-v21-sc-008).

## Technical Context

**Language/Version**: Lua 5.3.1 on the transmitter (32-bit integers and floats). Voice generator: Python 3.9+ (3.9.13 installed)

**Primary Dependencies**: JETI DC/DS Lua API v1.5 as declared in `types/jeti.lua`: `system`, `lcd` (incl. `lcd.renderer`), `form`, Jeti `io` (`io.open`/`io.close` to check voice files). Shared modules `ag_dens` and `ag_gauge`. Generator only (not deployed): `piper-tts` with the `en_US-amy-medium` model, Python standard library `wave`/`array`

**Storage**: `system.pSave`/`pLoad`, per model, 28 keys ([data-model.md](data-model.md)); migration `cfgV` 1 → 2. No files written by the app. Voice set: 512 generated WAVs in `AG-SpdGa/voice/`, gitignored

**Testing**: `python tools/check.py`; LuaLS diagnostics; optional `tests/test_ag_dens.lua` under any Lua 5.3 (none installed locally); the generator's self-check (file count, SC-009 durations); scripted emulator scenarios in [quickstart.md](quickstart.md); bench test on a test model

**Target Platform**: JETI DS-24 II / DC-24 II, firmware 6.03+ (emulator 6.04). Lua window sizes 157 × 60, 157 × 127 and 320 × 260 (measured; `docs/jeti-api-notes.md`). `lcd.renderer` needs V4.27+. Other transmitters get callouts and warnings, and a notice instead of the gauge (FR-013a)

**Project Type**: Embedded transmitter app (single Lua script, asset folder, shared lib modules) plus a developer-side generator script

**Performance Goals**: Gauge reflects speed within 0.5 s (SC-005); logic tick 100 ms; worst single call below 50% of the per-call budget, full screen included (SC-007, revised); number-only callout ≤ 1.3 s up to 199 and number-to-unit pause < 0.15 s (SC-009)

**Constraints**: No allocation in `loop()` or the print function, except at callouts (one path concatenation) and on a temperature change (rebuilding cached strings, at most every 5 s); call `system.getSensor*` through `system` each time (research R3); `lcd` only in print functions; `form` only while the form is open (tracked with `formOpen`, R17); ≤ 30 persisted keys; no `os`/`debug`/`coroutine`/`bit32`; never `registerControl`/`setControl`/`setProperty`; voice files never committed (FR-035)

**Scale/Scope**: App 1,016 lines today, about +250 for 0.2.0; two modules unchanged; generator ~200 lines; 5 reused WAVs + 512 generated

All unknowns are resolved in [research.md](research.md) or turned into
early checks. Still open, each with a fallback:

- whether the transmitter plays 22.05 kHz WAV (R13; fallback `--rate 44100`);
- the pause between two queued files (R14, SC-009; check by ear);
- how a temperature unit string is encoded on the transmitter (R15; the filter accepts both encodings);
- from 0.1.0: whether `°` renders (T039), the device string on a real
  transmitter, and the CPU figure (T029).

Inside `AG-SpdGa.lua`, sections follow `docs/examples/style/HELLO.lua`:
constants and persisted keys → settings and derived values → session state →
helpers (unit tables, recompute functions, voice helpers, temperature
reader) → settings form → print function → `init` / `loop` / `destroy` →
`return { ... }`. `APP_VERSION` becomes "0.2.0".

**Structure Decision**: The repo's standard app layout (constitution V, VII).
`tools/voice/` holds the generator because it is a developer tool, like
`tools/probe/`. The generated set lands in the app's asset folder so the
existing deploy step copies it, but git ignores it.
