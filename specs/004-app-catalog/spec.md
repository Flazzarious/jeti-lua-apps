# Feature Specification: Install docs and JETI Studio app catalog

**Feature Branch**: `feature/004-app-catalog`

**Created**: 2026-10-04

**Status**: Implemented (docs and tooling only; no app code changes)

**Input**: User description: "I'd rather document the manual install steps in
the readme and set up the catalog file." The user decided against an install
script.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Install by hand from the README (Priority: P1)

A pilot with the repo and a USB cable follows the README to put Speed Gauge
on the transmitter. The README says which files go where and in what
folders, and how to add the app on the transmitter.

**Independent Test**: Follow only the README's "Option B" on an empty
emulator `Apps` folder. Speed Gauge loads, its warnings and voice play, and
the gauge draws.

**Acceptance Scenarios**:

1. **Given** the README, **Then** it lists every item to copy (script, asset
   folder with the voice subfolder, the `lib` modules the app uses) and the
   exact destination of each.
2. **Given** the README, **Then** it says to install from a release tag, not
   from a working branch, and that folder names must not change.
3. **Given** the README, **Then** it covers updating (settings are kept) and
   the emulator.

### User Story 2 - Install from JETI Studio's catalog (Priority: P1)

A pilot adds this repo's catalog URL to JETI Studio once and then installs
or updates Speed Gauge from the Lua app manager. They never handle files.

**Independent Test**: Add the catalog URL in JETI Studio and install Speed
Gauge onto the emulator or a test transmitter. Every file lands in the same
place as a manual install, and the app runs.

**Acceptance Scenarios**:

1. **Given** the catalog, **Then** each app entry lists every file with a
   download URL, an SD-card destination under `Apps/`, a size and a SHA-1
   hash, in the format JETI Studio's catalogs use: JETI's own, LeonAirRC's
   and DFM's.
2. **Given** a catalog entry, **Then** its URLs point at the app's release
   tag (`<script>-v<version>`), so an install gets exactly the released
   files.
3. **Given** a release, **Then** the catalog is regenerated by a script, not
   edited by hand, and a check mode confirms it matches the tag.

### Edge Cases

- **Catalog committed before the tag exists**, per the release order in the
  README. Its links don't resolve until the tag is pushed, so the README says
  to tag immediately after merging.
- **App files changed on `develop` after a release.** They don't affect the
  catalog, which points at the tag.
- **Unconfirmed hardware codes.** The catalog limits apps to hardware codes
  3866 and 3867. 3867 is the DS-24 II, as reported by the JETI Studio
  emulator. 3866 is assumed to be the DC-24 II because DFM's catalog lists
  the two together. If JETI Studio doesn't offer the app for a 24 II, these
  codes are the first thing to check.

## Requirements *(mandatory)*

- **FR-001**: The README MUST document manual installation, updating and
  emulator installation for every released app (User Story 1).
- **FR-002**: The repo MUST publish `catalog/apps.json` in JETI Studio's
  catalog format. It is generated by `tools/catalog/make_catalog.py` from
  `catalog/sources.json` and the committed app files.
- **FR-003**: Catalog file URLs MUST be `raw.githubusercontent.com` URLs
  at the app's release tag. The repo is public, so no login is needed.
- **FR-004**: An app's catalog files MUST be its script, every committed
  file in its asset folder, and the `lib/` modules it `require`s
  (transitively).
- **FR-005**: `make_catalog.py --check` MUST fail when a release tag is
  missing, or when any tagged file's size or hash differs from the catalog.
- **FR-006**: The README's release steps MUST include regenerating the
  catalog before the release merge and running the check after tagging.

## Success Criteria *(mandatory)*

- **SC-001**: Every file in the catalog downloads from its URL with the
  catalog's size and SHA-1. Verified 2026-10-04 for all 548 Speed Gauge
  0.3.0 files.
- **SC-002**: An install from the catalog and a manual install produce the
  same files in the same places. To be confirmed in JETI Studio.

## Assumptions

- **Catalog format.** JETI Studio's format is taken from three published
  catalogs: JETI's, LeonAirRC's and DFM's. Each is an `applications` list;
  each app has `id`, `name`, `author`, `version`, `releaseDate`, `hw`,
  `description`, `previewIcon` and `files`. The hash is SHA-1, confirmed
  against a LeonAirRC file.
- **Source code shipped.** The catalog ships `.lua` source, not compiled
  `.lc`, since the constitution keeps `.lc` out of the repo.
