# Implementation Plan: Flameout Alarm

**Branch**: `feature/003-flameout-alarm` (merges to `develop`, then `main` on release) | **Date**: 2026-10-04 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/003-flameout-alarm/spec.md`

## Summary

A new app, **Flameout Alarm** (`src/Apps/AG-FlmOt.lua`), that watches a
turbine's RPM telemetry sensor and sounds an urgent, repeating alarm when
the engine spools down after it has been running. It arms only once RPM
has held at or above an arming threshold (a percentage below the typed-in
ECU idle) for the arming time, so start-ups, the start overshoot, throttle
chops and Cut-switch shutdowns never alarm. A double-size telemetry window
shows RPM as a segmented sweep bar with an idle marker and a large number.

Approach:

- **One app file, no lib modules.** Nothing here has a second user yet
  (Speed Gauge's R2 rule), so the install is just the script and its asset
  folder (FR-033).
- **A four-state machine on a 100 ms tick** (OFF, DISARMED, ARMED,
  FLAMEOUT) with telemetry validity tracked alongside, using one timestamp
  per condition. Cut is checked first and wins (research R8).
- **Each alarm cycle is one 5.000 s WAV** (callout plus lock tone) played
  with `AUDIO_IMMEDIATE`, which pre-empts other apps' speech; the
  telemetry-lost variant is a second 5 s file. `stopPlayback` silences it
  at once (R2–R4).
- **Sounds generated by a new script**, `tools/voice/make_flameout.py`,
  reusing Speed Gauge's voice helpers without changing them. The urgent
  pitch, EQ and compression are done in Python, no ffmpeg (R5).
- **Window drawn from precomputed segment geometry** with opaque renderer
  fills, the cheap kind of drawing per Speed Gauge's measurements (R11).
- **Repeatable testing without an engine**: an emulator RPM sensor plus a
  debug `SIM` mode that plays scripted RPM profiles (R12), and a **test
  alarm switch** that plays the real alarm on the transmitter, where sound
  can actually be heard (R13).

## Technical Context

**Language/Version**: Lua 5.3.1 on the transmitter (32-bit integers and floats). Sound generator: Python 3.9+ (3.9.13 installed)

**Primary Dependencies**: JETI DC/DS Lua API v1.5 as declared in `types/jeti.lua`: `system` (`getSensors`, `getSensorValueByID`, `getInputsVal`, `playFile`, `stopPlayback`, `playBeep`, `vibration`, `registerForm`, `registerTelemetry`, `pSave`/`pLoad`, `getTimeCounter`, `getDeviceType`, `getCPU`), `form`, `lcd` (incl. `lcd.renderer`), Jeti `io` (`io.open`/`io.close`). All are already declared; no new stubs. Generator only (not deployed): `piper-tts` (installed) with `en_US-amy-medium`, and `tools/voice/make_voice.py`'s helpers

**Storage**: `system.pSave`/`pLoad`, per model, 17 keys ([data-model.md](data-model.md)). No files written by the app. Five generated WAVs plus `CREDITS.txt` in `src/Apps/AG-FlmOt/`, committed, CC BY-SA 4.0

**Testing**: `python tools/check.py`; LuaLS diagnostics; the generator's self-check; emulator scenarios with Emulated Telemetry and `SIM` profiles ([quickstart.md](quickstart.md)); transmitter checks for sound and layout; bench test with a real ECU

**Target Platform**: JETI DS-24 II / DC-24 II, firmware 6.03+ (emulator 6.04). Transmitter window sizes 150 × 68 (double) and 150 × 23 (single); emulator 157 × 127 / 157 × 60 with the title inside. The alarm works on any DC/DS transmitter; the sweep needs a DS-24 II

**Project Type**: Embedded transmitter app (single Lua script plus asset folder) and a developer-side sound generator

**Performance Goals**: Alarm starts within detection delay + 0.5 s (SC-001); cycle every 5 s ± 0.3 s with no gap (SC-012); relight clears within arming time + 0.5 s (SC-011); display follows RPM within 1 s (SC-013); `loop()` near zero when OFF (FR-034); no CPU-limit errors over 30 minutes (SC-008)

**Constraints**: No allocation in `loop()` or the print function, except rebuilding `rpmText` when RPM / 100 changes; call `system.getSensor*` through `system` each time; `lcd` only in the print function; `form` only while the form is open; ≤ 30 persisted keys; ≤ 200 file-level locals (group constants in tables); no `os`/`debug`/`coroutine`/`bit32`; never `registerControl`/`setControl`/`setProperty`; intbox values ≤ 32,767 (RPM entered in hundreds)

**Scale/Scope**: App about 700–900 lines (Speed Gauge is 1,643); generator about 250 lines; 5 WAVs

All unknowns are resolved in [research.md](research.md) or turned into
transmitter checks with a fallback:

- gap between `playBeep` repeats (R6; fallback timing adjustable);
- the firmware's own telemetry "valid" timeout (R9; measured, documented);
- CPU cost of the sweep (R11; drop outlines, then straight bar);
- which ECUs beyond JetCat, Xicoy, KingTech and Swiwin-via-VSpeak expose RPM
  as a sensor (R1; README lists what is known).

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

| Principle | Status | How the design complies |
| --- | --- | --- |
| I. Nothing flight-critical | PASS | Reads one sensor and one switch, plays audio, vibrates, draws. No `registerControl`, `setControl`, `setProperty`, gpio or serial. The Cut switch is only read. If the app stops, the model and the ECU are unaffected (FR-032) |
| II. Everything local | PASS | All symbols `local`; constants, colors and segment geometry grouped in tables to stay well under 200 locals; one final `return` |
| III. Transmitter APIs only | PASS | Every call listed in Technical Context is declared in `types/jeti.lua`; Jeti `io` function style; `math`/`string` only. The generator runs on the PC |
| IV. State resets on model switch | PASS | Session state built in `init()`; 17 `pSave` keys (ints, one string, two SwitchItems); RPM and seconds stored as scaled integers; load clamps and validates |
| V. Stable names, UTF-8 | PASS | `AG-FlmOt.lua` (8.3, permanent at release), assets in `AG-FlmOt/`, absolute `/Apps/AG-FlmOt/...` paths; labels avoid characters outside the charset ("x" for "×") |
| VI. Keep loop() light | PASS | 100 ms tick; immediate return when OFF; `getSensorValueByID`; thresholds precomputed; file checks only in `init()`; cached strings; form rows touched only while `formOpen` |
| VII. Shared code in lib, stateless | PASS | No lib module added or changed, so no other app needs re-verification. `make_voice.py` (a tool, not a lib) is imported but not modified |
| VIII. License and credit | PASS | Original app, not derived from another author's code: SPDX header, no third-party credit needed for code. Piper (MIT) and Amy (CC BY-SA 4.0) credited in `AG-FlmOt/CREDITS.txt`, `CREDITS.md`, the README and the settings footer (FR-028). The ECU telemetry app in R1 was studied for facts only, not copied. The Haltech screenshot stays local; the committed mockup is original |

**Post-design re-check (2026-10-04):** PASS. The contracts add no API
beyond the table. Two patterns need care during implementation:
`form.setValue`/`setProperties` from `loop()` only while `formOpen`

Inside `AG-FlmOt.lua`, sections follow `docs/examples/style/HELLO.lua`:
constants (paths, colors, layout) → settings, keys and limits → derived
values and recompute → session state → audio helpers → state machine →
settings form → print function and layouts → `init` / `loop` / `destroy` →
`return { ... }`. `APP_VERSION` starts at "0.1.0".

**Structure Decision**: The repo's standard single-app layout (constitution
V). The generator sits in `tools/voice/` next to Speed Gauge's because it
shares its helpers and voice model. No `lib/` module: the only candidates
(file check, number formatting) are a few lines each and have no second
user that needs them shared.

## Implementation order

For `/speckit-tasks`. Each step leaves `check.py` passing.

1. **Sound generator** (R5): `make_flameout.py` with DSP, lock tone, cycle
   assembly and self-check; generate and listen on the PC; README section.
2. **App skeleton**: header, constants, settings keys with load/clamp/
   validate, recompute, `init` registering form and window, OFF window.
3. **Settings form** ([contract](contracts/settings-form.md)): sensor list
   with "(not found)", scale, live RPM, idle/max, thresholds with refusal,
   times, Cut switch, confirmations, test switch, enable rules, voice
   status.
4. **State machine** ([data-model.md](data-model.md)): tick, Cut first,
   validity and loss, arm, detect, relight, cycle timing.
5. **Audio** ([contract](contracts/audio-events.md)): file checks, cycle
   and telemetry-lost files, stop, confirmations, fallback beeps,
   vibration, test alarm (R13).
6. **Window** ([contract](contracts/telemetry-window.md)): layout selection,
   segment geometry, double, single and text layouts, number cache.
7. **Test support** (R12): emulator sensor in `sensors.json`; `SIM`
   profiles; `DEBUG_CPU`.
8. **Docs and credits**: README (row, advisory, ECU list, idle and
   threshold guidance per FR-035), CREDITS.md, CLAUDE.md table, generator
   README.
9. **Validation**: quickstart sections 1–2 in the emulator; sections 3–4
   on the transmitter and the bench (manual, reported by the user).
