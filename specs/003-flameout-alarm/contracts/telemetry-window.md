# Contract: Telemetry window

One window: `system.registerTelemetry(1, "Flameout Alarm", 0, printRpm)`.
Size 0 lets the pilot place it at single or double size. Full screen is out
of scope (FR-031c). Design: [design/rpm-window-mockup.svg](../design/rpm-window-mockup.svg),
regenerated by `design/mockup.py`. Decisions: research R11.

## Layout selection

```
if w == 157 then h = h - 26 end   -- emulator draws its title inside (Speed Gauge)
if not isDs24II   -> text layout
elseif h >= 45    -> double layout (transmitter 150 x 68)
else              -> single layout (transmitter 150 x 23)
```

Coordinates below are for the transmitter's 150 × 68 / 150 × 23 windows.
In the emulator (157 wide) the layout is offset 3 px right.

## Text layout (not a DS-24 II)

Theme foreground color: state label on the first line, RPM number on the
second (`FONT_NORMAL`). FLAMEOUT drawn the same way; the alarm itself
works on any transmitter.

## Rules

- Nothing is allocated per frame: segment points are computed in `init()`
  per layout (integer arrays); `rpmText` is rebuilt only when RPM / 100
  changes (data-model.md).
- One `lcd.renderer()` created on first draw and reused (verified on the
  transmitter with Speed Gauge).
- `lcd` calls only here (constitution VI).
- Fonts measured on the transmitter: `FONT_MINI` 12, `FONT_NORMAL` 17,
  `FONT_BIG` 20 px high.
- **Iteration points** (named constants): segment count, curve exponent,
  height range, number position. If the sweep reads poorly or the CPU figure
  is high, first drop the unlit outlines, then use the straight-bar layout at
  double size with the number above the bar (FR-031 fallback).
